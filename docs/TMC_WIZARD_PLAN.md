# План внедрения нового мастера для выдачи ТМЦ

Документ фиксирует шаги по реализации пошагового процесса выдачи материалов и оборудования сотруднику (аналогично flow «Новое подключение»), учитывая обсуждение в текущем диалоге.

---

## 1. Цели

1. Ускорить выдачу ТМЦ — все категории за одно прохождение.
2. Разгрузить оператора (ЗАВ склада) от ручного выбора каждой сущности в разных меню.
3. Сохранить читаемость истории: каждый шаг отправляет отдельное сообщение с результатом (как «Шаг X/17» в подключениях).
4. Показать текущие остатки сотрудника при выборе моделей (для каждого ТМЦ).

---

## 2. Общая архитектура решения

1. Добавить новый ConversationHandler (`tmc_record_conv`) в модуле `handlers/employees/tmc_flow.py`.
2. В `config.py` определить набор состояний:
   - `TMC_SELECT_EMPLOYEE`
   - `TMC_ENTER_FIBER`, `TMC_ENTER_TWISTED`
   - `TMC_SELECT_ROUTER`, `TMC_ENTER_ROUTER_QTY`
   - `TMC_SELECT_SNR`, `TMC_ENTER_SNR_QTY`
   - `TMC_SELECT_ONU`, `TMC_ENTER_ONU_QTY`
   - `TMC_SELECT_MEDIA`, `TMC_ENTER_MEDIA_QTY`
   - `TMC_SELECT_SFP`, `TMC_ENTER_SFP_QTY`
   - `TMC_CONFIRM`, `TMC_COMMENT`
3. `EmployeeFlow` расширить методами вызова tmc_flow (аналогично существующим `select_employee_for_media` и т.д.).
4. Раздел «Материалы и оборудование» (`handlers/employees/start.py`) дополнить пунктом «📦 Выдача ТМЦ», который запускает новый flow.
5. Данные по выдаваемым позициям хранить в `context.user_data['tmc_data']`, структура:
   ```python
   {
       'employee_id': ...,
       'fiber': 0/float,
       'twisted': 0/float,
       'router': {'model': '...', 'qty': 0},
       ...
       'comment': '...'
   }
   ```
6. После подтверждения мастер вызывает соответствующие методы `Database` (`add_material`, `add_router_to_employee`, `add_onu_to_employee`, `add_sfp_module_to_employee` и т.п.).

---

## 3. Детализация шагов мастера

### Шаг 0. Запуск и выбор сотрудника
- Список сотрудников с кратким обзором остатков (как в текущем меню).
- Сохраняем выбранного в `tmc_employee_id`.

### Шаг 1. ВОЛС (`TMC_ENTER_FIBER`)
- Сообщение: «Шаг 1/8: ВОЛС».
- Отображаем текущий остаток.
- Reply-клавиатура: ввод числа + кнопка «⏭️ Пропустить» + «❌ Отмена».
- При вводе — сохраняем `fiber_meters`, показываем итоговое сообщение «✅ ВОЛС: X м» (или «⏭️ Пропущено»).

### Шаг 2. Витая пара (`TMC_ENTER_TWISTED`)
- Аналогично шагу 1, но для витой пары.

### Шаги 3–7. Оборудование
- Последовательность: Роутеры → SNR → ONU → Медиаконверторы → SFP.
- Для каждого:
  - Сообщение вида «Шаг 3/8: Роутеры сотрудника …».
  - В inline-клавиатуру выводим:
    - популярные модели (из справочника) + количество из `db.get_employee_*`.
    - опцию «Ввести вручную».
    - «⏭️ Пропустить» и «❌ Отмена».
  - После выбора модели отдельное сообщение с запросом количества (reply-клавиатура с «Пропустить»).
  - Сохранение модели/количества в `tmc_data`.
  - Результирующее сообщение «✅ Роутер: Keenetic Racer x2» либо «⏭️ Пропущено».

### Шаг 8. Комментарий (опционально)
- При необходимости ввод комментария к операции.
- Значение сохранять в `tmc_data['comment']`.

### Финальный шаг. Подтверждение
- Сформировать сводку всех введённых полей.
- Кнопки: «✅ Подтвердить», «✏️ Изменить» (возврат к первому шагу?), «❌ Отмена».
- При подтверждении вызвать методы `db.*`:
  - Материалы — `add_material`.
  - Роутеры/оборудование — `add_*_to_employee`.
  - Передавать `created_by`, `comment`.
- После успешного завершения выводим итог и очищаем `context.user_data`.

## 4. UI/UX требования

1. **История шагов** — каждый этап отправляет сообщение (аналогично «Новое подключение»), чтобы в чате оставался «след» с результатами.
2. **Текущие остатки**:
   - Перед выбором модели отображать текущие количества у сотрудника.
   - В названии кнопок выводить `Модель (qty шт.)`.
   - Если qty = 0, отображаем «(нет)» или «(0 шт.)» для видимости.
3. **Клавиатура отмены/пропуска** — на каждом шаге присутствует `⏭️ Пропустить` и `❌ Отмена`.
4. **Единый стиль шагов** — формат `"<emoji> Шаг X/8: Описание"` + текстовые подсказки.

## 6. Проверка и валидация

1. Пройти сценарий со всеми шагами, убедиться, что история сообщений читаема.
2. Тесты:
   - Полное заполнение всех полей.
   - Пропуск части категорий.
   - Отмена на любом шаге.
   - Повторный запуск мастера.
3. Проверить записи в БД (`employee_*` таблицы), что количества увеличиваются корректно.
4. Убедиться, что списание в разделе «Материалы и оборудование» не изменено.
